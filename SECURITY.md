# Security Policy

## Reporting a vulnerability

> [!IMPORTANT]
> Reports must be written and verified by a human, not generated by AI. If you are using AI to submit a vulnerability, follow the rules in [AI_POLICY.md](https://github.com/getarcaneapp/arcane/blob/main/AI_POLICY.md). CVE farming and other low-effort submissions are disrespectful and put the burden of validation on the volunteer maintainers of this project—they may be closed without review.

> [!IMPORTANT]
> If you discover a security vulnerability, do not open a public GitHub issue. Public disclosure can expose users to risk before a fix is available.

- Report vulnerabilities privately by emailing [info@getarcane.app](mailto:info@getarcane.app).
- For regular bugs or feature requests, use the [GitHub issue tracker](https://github.com/getarcaneapp/arcane/issues).

## Trust model and scope

Arcane is a management layer on top of Docker and Podman. Understanding where the container runtime ends and Arcane begins helps avoid invalid reports:

- **Out of scope — container runtime bugs:** Vulnerabilities in Docker, Podman, or the container daemon itself belong upstream with those projects, not in this repo.
- **Out of scope — inherent runtime capabilities:** Giving a user admin access or permission to create/modify containers, stacks, or bind mounts inherently grants broad control over the host. That is how Docker and Podman work by design, not an Arcane vulnerability.
- **Out of scope — non-production or already-trusted access:** Dev-mode or maintainer-only features, and attacks that already require host root or global admin access.
- **In scope:** Bugs in Arcane itself, such as authentication bypasses, RBAC or permission escalation (for example, a read-only role escaping into host files or resources it should not access), injection flaws, or leaks in Arcane's API, UI, or agent tunnel.

## What to include

- A clear description of the issue and its real-world impact.
- Step-by-step reproduction instructions and affected versions or environments.
- A suggested fix or mitigation if you have one.

## What to expect

- We will acknowledge your report as soon as we can.
- We will investigate, validate the issue, and work on a fix.
- We will keep you updated as we prepare and ship the release.
